# Grid Suite — полный цикл: анализ → оптимизация → торговля

Комплект из двух связанных инструментов:

```
grid-suite/
├── lab/    Лаборатория: бэктест на реальной истории + оптимизатор
├── bot/    Торговый бот: автономная сетка с защитами и Telegram
├── termux-setup.sh / termux-run.sh    Установка и запуск на телефоне
└── README-TERMUX.md    Инструкция для запуска в Termux (Android)
```

## Полный цикл за 4 команды

```bash
# 1. Установка (один раз)
pip install -r lab/requirements.txt -r bot/requirements.txt

# 2. Оптимизация: находит параметры, устойчивые на 30/90/180 днях,
#    и сама вписывает их в конфиг бота
cd lab
python optimize.py --symbol BTCUSDT --apply ../bot/config.yaml

# 3. Ключи и Telegram (один раз): bot/README.md, шаги 2-4
cd ../bot
copy .env.example .env    # и заполнить

# 4. Запуск на testnet
python bot.py
```

## Почему связка устроена именно так

**Оптимизатор оценивает по худшему отрезку, а не по лучшему.** Комбинация,
давшая +20% за удачные 90 дней и −15% за другие 30, проиграет комбинации
со скромными +3% на всех отрезках. Это защита от главной ошибки новичков —
подгонки параметров под один счастливый кусок истории.

**Оптимизатор откажется записывать заведомо плохое.** Если даже лучшая
комбинация в минусе хотя бы на одном отрезке, он предупредит: рынок этой
монеты сейчас не для грида — и спросит подтверждение.

**Человек остаётся в цикле в двух местах.** Запись в конфиг при плохих
результатах и рестарт после лимита просадки требуют твоего «да». Всё
остальное — автоматика.

## Регулярное обслуживание (раз в 2-4 недели)

Рынок меняется, параметры устаревают. Раз в пару недель:
```bash
cd lab
python optimize.py --symbol BTCUSDT --apply ../bot/config.yaml
```
Затем перезапусти бота (Ctrl+C -> y -> запуск). Старый конфиг всегда
в config.yaml.bak.

ВАЖНО: не переоптимизируй чаще. Ежедневная подгонка параметров — это
та же подгонка под шум, только в профиль.
